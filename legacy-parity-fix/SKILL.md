# 翻新页面单点修复（对齐旧系统）

适用于一个页面或一个弹窗的局部问题。整模块翻新、需求提取不走本技能。

## 0. 开工前锁定

先确认下面五项。能从用户消息、打开的文件、`git status`、`git branch --show-current` 推断的直接用，并在第一句回复里写出来：

1. 仓库与分支。工作区同时打开多个仓库时，必须写明改哪一个。
2. 页面路由与 Vue 文件。
3. 旧系统对应的 `.cshtml` / SeaJS 文件。
4. 预期行为，一句话。
5. 不许动的范围。用户没说时默认：公共组件（`@components`）、全局样式、其它页面、与问题无关的字段和文案。

只有仓库或分支无法确定时才停下来问。动手前先看 `git status`，记下已有的未提交改动，后面不得覆盖。

## 1. 找旧系统证据

- 从菜单或页面入口找到旧代码，记录 `文件:行号`。Razor、SeaJS、模板和 `data-control` 配置算同一条链路。
- 被注释掉的旧代码不算旧行为。
- 找不到证据就明说找不到，不要按经验补写。
- 数据源对照先查 `~/.agents/skills/cshtml-to-vue3/references/legacy-data-source-mapping.md` 和同目录的 `dict-enum.md`；select 是否加 `mode="search"` 看 `~/.agents/skills/hcgselect-mode-search/SKILL.md`。

## 2. 只比对与本问题相关的项

- 显隐与权限条件。
- 默认值、清空与联动。
- 校验规则与触发时机（change / blur / 保存时）。
- 提示文案：逐字照旧系统，不新增提示。接口报错由全局封装提示，不在 `catch` 里再弹 `ElMessage`。
- 数据源与字典反显：按 ID 走字典反显，不直接取 name，不写 `|| row.xxxName || '-'` 这类兜底。旧 suggest/select 要核对"设置常用数据"的源码标识和目标组件参数，不能只看控件名。
- 提交参数：区分 `0`、空字符串、`null` 和不传。
- 成功和失败之后的交互：关闭、刷新、跳转。

## 3. 修改

- 只改有差异的行，不顺手重构，不改字体、间距和公共组件。
- 撤回自己的改动时，按 diff 只回退那几处。不要用 `git checkout <文件>`、`git restore <文件>`、`git reset --hard`、`git clean`，它们会连同已有的未提交改动一起删掉。
- 不提交、不推送、不合并、不切分支，除非用户在本次对话里明确要求。

## 4. 交付

- 逐处列出：`文件:行号`、改了什么、依据（旧系统 `文件:行号`，或用户原话）。没有依据的改动删掉。
- 对改动的文件运行项目已有的 lint 和类型检查，报告结果。
- 写清楚自测了哪些操作、看到什么结果。没有运行环境就写"未自测"，不写"已修复"。

## 开场模板（给用户复制）

```

现象：
```
