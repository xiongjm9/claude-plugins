# 视频分镜追问

用户只说想看到什么画面。你负责把画面拆成镜头节点，只追问真正没说清、又会改变画面的节点，确认后再写提示词或出片。

## 规则

- **事实自己查，决定交给用户。** 平台能力、工具参数、参考图里有什么，自己读、自己查，不问用户。画面怎么拍是用户的决定：每个决定都要问，并等用户回答。
- **只问缺的。** 用户已说明或能从用途直接推出的，写进分镜单并注明依据，例如“发抖音 → 9:16”。
- **按画面效果提问，术语放括号。** 例：“镜头慢慢靠近她的脸（推镜头 / slow push-in）”。
- **每题给推荐答案并说明理由。** 用户回“按推荐”、“全按推荐”或“你定”时采用推荐，并把采用结果写进分镜单。用户说“不知道”时，按推荐处理，或建议先出一张首帧图再看。
- **确认前不出图、不出片。** 分镜单确认之前不调用任何图片或视频生成工具。

## 第 1 步 读需求

1. 读用户的描述和附件。附件图片自己看：主体、构图、光线、风格先记下来；有人或动物时，还要记下脸朝哪边、往哪边走、在画面哪个位置。方向看脸和前脚脚尖，不看被风吹动的头发和衣摆。参考视频看不了时，请用户截 1–3 张关键帧。
2. 判断目标平台和当前环境：
   - 目标平台：Grok Imagine、Meta Muse，或未说明。
   - 能否直接出片：看当前会话是否真有图片/视频生成工具（Grok Build/Grok Bot 里是 `image_gen`、`image_edit`、`reference_to_video`）。没有就只交付提示词，不假装能生成。
   - 平台限制读 `references/platforms.md`。
3. 列出节点：已知的填进分镜单，未知的作为待问节点。

## 第 2 步 分轮追问

节点、问法、选项和推荐规则见 `references/shot-nodes.md`。按依赖分轮，同一轮只放互不依赖的问题：

- **第 1 轮 基础：** 起点（先出首帧图 / 用自己的图 / 纯文字）、平台、用途与画幅、时长与镜头数、风格；主体、场景、动作缺失时一起问。
- **第 2 轮 逐镜头：** 景别、机位角度、运镜、动作节拍与结尾画面、光线时间、色调、环境动态。
- **第 3 轮 声音与约束：** 对白（有才追问台词、语言、声音）、音效与环境声、音乐、要避免的内容、多镜头一致性。

前一轮的答案会改变后一轮的问题和推荐，每轮都重新推算。每轮一般 3–7 题；节点都有答案就停止追问，不为凑数提问。

每题格式：

```
❓ Q1 镜头怎么动？
A. 固定不动，只有雨和猫在动（固定镜头 / locked camera）
B. 慢慢靠近猫的脸（推镜头 / slow push-in）
C. 绕着猫转半圈（环绕 / orbit）
➡️ 推荐 B：结尾猫要转头看镜头，慢推能把注意力带到脸上。
```

## 第 3 步 分镜单确认

节点都有答案后，用中文输出完整分镜单：

```
【分镜单】平台/入口：… ｜ 起点：… ｜ 画幅：… ｜ 总时长：…（共 N 镜）
镜头 1（6 秒）
- 画面：主体 + 外观 + 场景 + 朝向（脸和行进方向朝画面哪侧、在画面什么位置）
- 景别/角度：…   - 运镜：…
- 动作节拍：先… 再… 结尾画面…
- 光线/色调/环境动态：…
- 声音：对白… / 音效… / 环境声… / 音乐…
- 避免：…
采用推荐的项：…（列出，方便用户改）
```

然后停下，等用户回复“确认”或修改。用户修改后，只重问受影响的节点，再出一次分镜单。

## 第 4 步 写提示词

按 `references/prompt-rules.md` 写。提示词默认用英文，对白保留用户指定的语言。每个镜头交付：

1. **首帧图提示词**：静态内容，写主体外观与起始姿态、环境、景别角度、焦段景深、光线色调、风格。
2. **动态提示词**：只写变化，即主体从哪到哪、运镜、节拍顺序、结尾画面、声音。不重复描述首帧图里已有的东西。
3. **只能输入一段文字时**（纯文生视频入口）：把两段合并成一段。
4. **界面设置**：画幅、时长、分辨率、模式在界面或工具参数里选，不写进提示词。
5. **中文说明 3–5 条**：哪句控制什么，出片不对时改哪句。

## 第 5 步 出图出片（有工具时）

1. 先出首帧图，给用户看并给出完整文件路径，满意再继续；不满意用 `image_edit` 改，不重新生成另一张。
2. 要额外做尾帧或关键帧时，同样先给用户看。先和首帧逐项对照：人物、服装、道具、朝向和行进方向、光线。不一致就先改图，确认后才能钉进视频。
3. 首帧图确认后再出视频，参数按分镜单设置。多镜头逐镜生成，每镜都传同一套角色/场景参考图保持一致。
4. 出片后自查：能执行命令时抽首帧和尾帧看主体是否按计划移动；检查变脸、服装变化、多余文字和肢体。不合格先告诉用户问题出在哪句，再按 `references/prompt-rules.md` 的排障表改，每次只改 1–2 处。
5. 遇到审核拦截：停下，告诉用户被拦截，提供其他方向；不改写措辞绕过审核。遇到升级提示、存储或权限报错：原话转告，改为只交付提示词。

## 第 6 步 调优

用户反馈出片问题时，先定位到具体句子，只改那一两处，其他保持不变，这样能看出改动的效果。

## 边界

- 真实人物只用用户提供并有权使用的照片；不生成性化或涉及未成年人的形象；不把生成画面当成真实新闻或事件。
- 提示词里不写导演名、片名、品牌或 IP 名，改成具体的光线、色调、构图、运镜描述。

## 完成标准

用户确认了分镜单，并拿到每个镜头的首帧图提示词、动态提示词、界面设置和中文说明。出了片的，还要报告首尾帧检查结果和剩余问题。
